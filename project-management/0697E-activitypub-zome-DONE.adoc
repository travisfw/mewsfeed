== Abstract

This specdoc delivers the `activitypub_integrity` and `activitypub` coordinator
zome pair, wired into the mewsfeed DNA. The zomes persist ActivityPub
federation state on the DHT using types from
link:../crates/activitypub_types/[`activitypub_types`].

This is the Holochain-side implementation described in
link:0697D-activitypub-zome-PWOR.adoc[0697D]. The S2S module integration
(`ZomeDataSource`, integration server, round-trip tests) is deferred to 0697F.

**Status**: ✅ COMPLETE - Zomes implemented with deduplication pattern. ZomeDataSource
already exists in `activitypub-s2s/src/zome_data.rs` (contrary to 0697F plan assumptions).

Verification is build-only: WASM compilation of both zomes, workspace check,
and hApp assembly.

== Integrity Zome

Location: `dnas/mewsfeed/zomes/integrity/activitypub/`

=== Entry Types

Six entry types, all public visibility, reusing structs from `activitypub_types`:

[source,rust]
----
#[hdk_entry_types]
#[unit_enum(UnitEntryTypes)]
pub enum EntryTypes {
    InstanceConfig(InstanceConfig),
    MewFederationState(MewFederationState),
    RemoteActorRef(RemoteActorRef),
    RemoteFollow(RemoteFollow),
    RemoteFollower(RemoteFollower),
    RemoteInteraction(RemoteInteraction),
}
----

=== Link Types

[source,rust]
----
#[hdk_link_types]
pub enum LinkTypes {
    MewToFederationState,
    AgentToRemoteFollows,
    AgentToRemoteFollowers,
    MewToRemoteInteractions,
    AnchorToInstanceConfig,
    ApUriToFederationState,
    ActorUriToRemoteActorRef,
    FollowDedupToRemoteFollow,
    FollowerDedupToRemoteFollower,
    InteractionDedupToRemoteInteraction,
}
----

==== Deduplication Link Pattern

The last three link types implement O(1) idempotency checks using Path-based
anchors as composite-key indexes. Without these, duplicate detection would
require O(n) iteration through all existing entries.

For example, `create_remote_follow` creates a deterministic anchor from
`"follow:{agent}:{remote_actor_uri}"` and checks
`FollowDedupToRemoteFollow` links before creating new entries. This prevents
duplicate follows from ActivityPub retry storms or race conditions.

Trade-off: one extra link per entry (minimal DHT cost) for efficient duplicate
prevention at write time, critical for federation reliability.

=== Validation Rules

`MewFederationState`::
  The action author must be the author of the mew referenced by `mew_hash`.
  Validate via `must_get_action(entry.mew_hash)` and compare `.author` to the
  creating action's author. This is a cross-zome read (mew lives in
  `mews_integrity`).

`RemoteFollow`::
  `entry.local_agent` must equal the action author. This ensures agents can
  only create follow records for themselves.

`RemoteFollower`, `RemoteInteraction`::
  Permissive -- any agent may create these. The S2S gateway agent writes them
  on behalf of inbound fediverse activity.

`InstanceConfig`::
  Entry creation itself is permissive. The `AnchorToInstanceConfig` link
  enforces singleton behavior (see below).

`AnchorToInstanceConfig` link::
  First-write-wins. Integrity validation is permissive because `get_links` is
  not available in validation callbacks (validation must be deterministic).
  Singleton enforcement is handled at the coordinator level:
  `set_instance_config` calls `get_links` on the anchor and returns an error
  if a link already exists (see
  link:../dnas/mewsfeed/zomes/coordinator/activitypub/src/config.rs[`config.rs:15-21`]).

Other links::
  Permissive for initial implementation. The link base should correspond to
  the relevant field in the target entry (e.g., `MewToFederationState` base
  is the mew's `ActionHash`), but strict validation of this can be added
  incrementally.

=== Cargo.toml

[source,toml]
----
[package]
name = "activitypub_integrity"
version = "0.0.1"
edition = "2021"

[lib]
crate-type = ["cdylib", "rlib"]
name = "activitypub_integrity"

[dependencies]
hdi = { workspace = true }
serde = { workspace = true }
activitypub_types = { workspace = true }
----

Note: `activitypub_types` depends on `hdk`, but `activitypub_integrity` uses
`hdi`. The entry type structs only need `Serialize + Deserialize +
SerializedBytes` which both `hdk` and `hdi` re-export. If there is a
compilation conflict, the integrity zome can re-derive `SerializedBytes` on
newtype wrappers, or `activitypub_types` can be refactored to depend on `hdi`
instead of `hdk`. Evaluate at build time.

=== Extern Functions

Grouped by module. Input/output types use standard HDK patterns
(`ActionHash`, `AgentPubKey`, `ExternResult<...>`).

==== config.rs

`set_instance_config(config: InstanceConfig) -> ExternResult<ActionHash>`::
  Create `InstanceConfig` entry. Create `AnchorToInstanceConfig` link from a
  deterministic anchor (e.g., `hash_entry("federation_instance_config")?`).
  If the anchor link already exists, return error (singleton).

`get_instance_config() -> ExternResult<Option<InstanceConfig>>`::
  Get link from the singleton anchor, fetch the entry.

==== federation_state.rs

`create_mew_federation_state(state: MewFederationState) -> ExternResult<ActionHash>`::
  Create entry, link from `state.mew_hash` via `MewToFederationState`.
  If `state.ap_uri` is `Some`, also create `ApUriToFederationState` link.

`set_mew_ap_uri(input: SetApUriInput) -> ExternResult<()>`::
  Update the `ap_uri` field. Input contains `mew_hash: ActionHash` and
  `ap_uri: String`. Create `ApUriToFederationState` link.

`get_mew_federation_state(mew_hash: ActionHash) -> ExternResult<Option<MewFederationState>>`::
  Follow `MewToFederationState` link from the mew hash.

`get_mew_by_ap_uri(ap_uri: String) -> ExternResult<Option<MewFederationState>>`::
  Hash the URI string, follow `ApUriToFederationState` link.

==== remote_actors.rs

`upsert_remote_actor_ref(actor: RemoteActorRef) -> ExternResult<ActionHash>`::
  Hash `actor.actor_uri`, check for existing `ActorUriToRemoteActorRef` link.
  If exists, update entry; if not, create entry and link.

`get_remote_actor_ref(actor_uri: String) -> ExternResult<Option<RemoteActorRef>>`::
  Hash the URI, follow `ActorUriToRemoteActorRef` link.

==== remote_follows.rs

`create_remote_follow(follow: RemoteFollow) -> ExternResult<ActionHash>` *(idempotent)*::
  Create dedup anchor from `"follow:{agent}:{remote_actor_uri}"`. Check for
  existing `FollowDedupToRemoteFollow` link. If exists, return existing hash.
  Otherwise, create entry, link from `follow.local_agent` via
  `AgentToRemoteFollows`, and create dedup anchor link.

`update_remote_follow_status(input: UpdateFollowStatusInput) -> ExternResult<()>`::
  Input: `follow_hash: ActionHash`, `status: RemoteFollowStatus`.
  Fetch existing, create updated entry.

`list_remote_follows(agent: AgentPubKey) -> ExternResult<Vec<RemoteFollow>>`::
  Get links from agent via `AgentToRemoteFollows`, fetch entries.

`delete_remote_follow(follow_hash: ActionHash) -> ExternResult<()>`::
  Delete the entry, `AgentToRemoteFollows` link, and dedup anchor link.

==== remote_followers.rs

`create_remote_follower(follower: RemoteFollower) -> ExternResult<ActionHash>` *(idempotent)*::
  Create dedup anchor from `"follower:{agent}:{remote_actor_uri}"`. Check for
  existing `FollowerDedupToRemoteFollower` link. If exists, return existing
  hash. Otherwise, create entry, link from `follower.local_agent` via
  `AgentToRemoteFollowers`, and create dedup anchor link.

`list_remote_followers(agent: AgentPubKey) -> ExternResult<Vec<RemoteFollower>>`::
  Get links from agent, fetch entries.

`delete_remote_follower(follower_hash: ActionHash) -> ExternResult<()>`::
  Delete entry, `AgentToRemoteFollowers` link, and dedup anchor link.

==== remote_interactions.rs

`create_remote_interaction(interaction: RemoteInteraction) -> ExternResult<ActionHash>` *(idempotent)*::
  Create dedup anchor from `"interaction_activity:{activity_uri}"`. Check for
  existing `InteractionDedupToRemoteInteraction` link. If exists, return
  existing hash. Otherwise, create entry, link from `interaction.mew_hash` via
  `MewToRemoteInteractions`, and create dedup anchor link.

`list_remote_interactions(mew_hash: ActionHash) -> ExternResult<Vec<RemoteInteraction>>`::
  Get links from mew hash, fetch entries.

`delete_remote_interaction(input: DeleteRemoteInteractionInput) -> ExternResult<()>`::
  Input contains `mew_hash` and `activity_uri`. Scan `MewToRemoteInteractions`
  links to find the interaction with matching `activity_uri`. Delete entry,
  `MewToRemoteInteractions` link, and dedup anchor link.

==== cross_zome.rs

`get_agent_ap_profile(agent: AgentPubKey) -> ExternResult<Option<serde_json::Value>>`::
  Call `profiles` zome to get the agent's profile. Combine with
  `InstanceConfig` to construct a JSON blob suitable for the S2S module to
  build an `APActor`. Uses `hc_call_utils` for cross-zome calls.

`get_federated_mews_for_agent(agent: AgentPubKey) -> ExternResult<Vec<MewFederationState>>`::
  Call `mews` zome to get agent's mew hashes. For each, check
  `MewToFederationState` links. Return states where visibility is not
  `HolochainOnly`.

== Verification

=== Build gates

[source,bash]
----
cargo build -p activitypub_integrity --target wasm32-unknown-unknown --release
cargo build -p activitypub --target wasm32-unknown-unknown --release
cargo check --workspace
npm run build:happ
----

All four commands must succeed.

=== Consistency check

- Every entry type in the integrity zome enum corresponds to a struct in
  `activitypub_types`.
- Every link type in the integrity zome enum is referenced by at least one
  coordinator function. The three dedup link types are used in
  `create_remote_follow`, `create_remote_follower`, and
  `create_remote_interaction` for O(1) idempotency checks.
- The coordinator `lib.rs` exports all functions listed above as
  `#[hdk_extern]`.
- The DNA manifest lists `activitypub_integrity` and `activitypub` with correct
  paths and dependency declarations.
